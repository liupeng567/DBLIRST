## 1. 核验中新发现的问题（回应文档未覆盖）

### 1.1 无 git → 证据链断点（🔴 高）

回应文档把可信度锚在"已入 git（本次提交）"，但工作区**没有 `.git`**。"修复已提交到哪个 commit"无法被任何人复核，也无法回滚对比。这已是第二次出现（首轮评审 §2.5 第 1 条），说明它没被当成问题处理。

**处置**：`git init` + 首提交即可，同时把 `experiments/`、`data/cache/` 的**产物清单（hash 清单文件）**入库（大文件本身可外置），否则"可复现"仍然只是叙述。

### 1.2 870 个参考帧未入账，且 `success_rate` 分母含"不可能失败"的帧（🟡 中）

`reg_stats_corrected.json` 的帧桶求和：18,443 + 2,150 + 287 + 0 = **20,880 ≠ 21,750**。缺口 **870 = 87 × 10**，正是每段 `range(0, N, 25)` 的 **参考帧**（`method == "ref"`，`rmse ≡ 0.0`）。它们既不在 KLT 也不在 FM 桶里，却计入 `reg_ok = ~(failed | flat)`。

两个后果：

1. **旧口径的另一重"结构性通过"**：旧 `percentile(reg.rmse[reg_ok])` 把每段 10 个 `rmse ≡ 0.0` 的参考帧混进分布，**拉低** P95。新脚本的 `klt_ok` 口径已把这个污染排除（这是本次修复的隐含收益，但没人说明）。
2. **成功率分母偏乐观**：`success_rate = reg_ok.mean()` 把 870 个"不可能失败"的参考帧算作成功。剔除参考帧后，需要真正配准的帧为 21,750 − 870 = **20,880**，成功率 = 20,593/20,880 = **98.63%**，而非报告的 **98.68%**。

**处置**：帧桶补 `n_ref`（并显式标注 `rmse ≡ 0` 的定义性质）；`success_rate` 增加分母说明或改用"非参考帧"口径。量级小（0.05pp），但与 2.2a 是**同一类问题**，若不修，下一轮审计还会撞上。

### 1.3 FM 相关质量"最低 0.500"是构造性的，不是发现（🟡 中）

`register.py` 的 FM 分支仅在 `quality >= fm_corr_gate` 时返回 `"fm"`，而落盘 `rmse = 1 − quality`。因此 **FM 帧的 corr 恒 ≥ 门限**，`fm_corr_min = 0.50022 ≈ 0.5` 是**逻辑必然**，不是质量证据。回应文档写作"最低 0.500（**恰贴** FM 接受门限 0.5）"，把同义反复当成了观测。

**有信息量的是中位数**（`med_of_seq_med = 0.675`），以及**贴近门限的帧占比**（当前未统计）。

**处置**：把 `fm_corr_min` 改名为 `fm_corr_min_ge_gate`（明示下界性质），并新增 `fm_corr_below_055_frac`（或分位 p10/p25）作为真正的质量指标。这与 2.2a 修的是同一个病，但**下沉了一层没修干净**。

### 1.4 快评子集对配准退化的两端都不敏感；且训练/诊断存在配准域错配（🔴 高，直接影响 M3 判据）

由 [`split_rebalance_table.md:52`](m0/split_rebalance_table.md) 得 **val-int = [21,22,23,38,39,40,65,66,67,68,69,70]**，与配准统计交叉：

| 序列 | split | n_klt | n_fm | FM 中位相关 |
| --- | --- | --- | --- | --- |
| 21 / 22 / 23 / 38 | val-int（**快评子集＝前 4 段**） | 239 / 240 / 234 / 237 | 1 / 0 / 5 / 3 | — |
| **67** | val-int | **0** | **215** | 0.886 |
| **68** | val-int | **0** | **240** | 0.837 |
| 65 / 66 / 69 / 70 | val-int | 238 / 240 / 240 / 240 | 2 / 0 / 0 / 0 | — |
| **87** | **val-official** | **0** | **240** | 0.911 |
| **71** | train-int | **0** | **240** | 0.928 |
| 72 / 74 / 75 / 76 | train-int | 2 / 75 / 87 / 124 | 238 / 165 / 153 / 116 | 0.92 / 0.71 / 0.93 / 0.94 |

三条结论：

1. **快评子集 [21,22,23,38] 全为 KLT 主导**（FM 帧 ≤5/段），因此 `train.quick_eval` 对 **FM 配准域完全不可见**——早停与阈值校准所用的诊断集，避开了 val-int 里配准机制最特殊的两段（67/68）。
2. **训练集含 5 段 FM 主导**（71,72,74,75,76），而诊断集一段都没有 → **训练/诊断配准域错配**：模型在 FM 扭曲的帧上学习背景预测，却没有在同类帧上被诊断。
3. **val-official 含 seq 87（100% FM）** → 最终官方分中有 1/11 段的配准完全依赖 Fourier-Mellin。

**处置（成本极低）**：把 **seq 67 与 68 加入 `quick_eval` 固定子集**（`configs/dsld_core.yaml:61` 的 `n_seqs` 或子集列表），并让诊断集**同时覆盖 KLT 边际段**（KLT p95 ≈0.49：60/63/41/59/86/32）与 FM 主导段。

> 附带一个更准确的认识：4 段 100%-FM 的序列，其 FM 相关**中位数反而偏高**（0.84–0.93），说明 KLT 失败的原因是**低纹理**（角点不足）而非运动过大——FM 在这些场景并不差。真正的风险人群是**贴近门限的两类边缘帧**：KLT p95≈0.49 的段，与 FM corr 贴近 0.50 的帧（36/37/41/42/46/47/58/60/63）。计划应针对**边缘帧**，而不是"FM 帧"这个概念本身。

### 1.5 核心层仍未修的三条（🔴 高）——`bias = −2` 买的是裕度，不是边界

| 未修项 | 现状 | 为什么"已修 2.1"不等于安全 |
| --- | --- | --- |
| **不变量 0**：约束加在隐参数而非实现的保留系数 | `theta_tau` 在 **τ 域** clip（[`liquid_core.py:71-73`](../dsld/models/liquid_core.py)），门控仍为 `σ(−f·Δt/τ)`，`f` 自由 | τ 仍可被 `f ∝ τ` 抵消；`eff_tau = τ/|f|` 是**参数比值**，同样可被同步缩放掩盖 |
| **无显式泄漏项** | `h' = p·g + (1−p)·m`（[`:95`](../dsld/models/liquid_core.py)），`g`/`m` 均为 `[h,x]` 的 1×1 卷积 | 旧状态不是保留项 → 无记忆保证、状态无界（仍需范数哨兵）、时间尺度仍非结构 |
| **掩码无上界** | `update_feedback_mask` 返回 `max(dil, decay·M_prev)`，**上界为 1**（[`:115-125`](../dsld/models/liquid_core.py)） | `bias −2` 只把 α₀ 推到 0.119，**训练仍可把 α 推过阈值**；一旦成片越阈，M→1 → 双通道再次饿死。**同一个失效模式在结构上依然可达** |

即：**2.1 是"把故障推出启动区"，而不是"把故障排除出可行域"**。这一条必须在 M3 正式训练前解决，否则 50k 步训练仍可能在中途窒息（届时哨兵会报警，但已消耗算力）。

## 2. M3 核心层推进方案

原则：**先让机制可证伪，再花 GPU；先补分母，再谈结论。**

### 阶段 A — 核心层根因（0.5 天，无需 GPU，纯 CPU 单测即可验收）

| # | 动作 | 出口判据（可失败的合成单测） |
| --- | --- | --- |
| A1 | **不变量 0 落地**：`theta_tau` → `theta_lambda`（λ 域硬 clip），`a = exp(−Δt·λ)`，两通道 λ 区间取**不相交**值域（建议 τ_B∈[24,192]、τ_T∈[2,8]） | ① 任意输入喂 200 步，实现的 `a` **始终落在** `[exp(−λ_max), exp(−λ_min)]`；② 实测衰减 == `exp(−Δt·λ)`（容差 1e-5）；③ `τ_eff_B/τ_eff_T ≥ 3` **恒成立**（扫 1000 组随机权重） |
| A2 | **显式泄漏项**：`h' = a⊙h + (1−a)⊙tanh(cand)`（三头与 FiLM 全保留，`m` 降为候选精修项） | ④ 状态有界：`‖h‖ ≤ max(‖h₀‖,1)+ε` 喂 200 步；⑤ 脉冲响应半衰期比 ≥3（常数背景 + 单帧亮点） |
| A3 | **掩码上界**：`M = min(max(dil, γ·M_prev), m_max)`，`m_max=0.8`，`alpha_th=0.6` | ⑥ 任意 α 输入下 `max(M) ≤ 0.8` 且 `1−M ≥ 0.2`；⑦ `α≡0.119`（初始）时 `M ≡ 0` |
| A4 | **`L_dec` 加范数下限**：`cos²` 分母 `clamp_min(min_norm²)` + `relu(min_norm − min(n_t,n_b))` | ⑧ `h_T ≡ 0` ⇒ `L_dec > 0`（现实现必然为 0） |
| A5 | **快评子集改造**：加入 seq **67、68**（FM 主导）与一 KLT 边际段（如 60） | ⑨ 诊断记录里能同时看到两种配准域 |

A1–A4 的代码落点与 before/after 已在 [`reports/双状态液态核_设计文档与补丁草案.md`](双状态液态核_设计文档与补丁草案.md) §5–§6 给出，**不再重复**；A5 只需改 `configs/dsld_core.yaml` 的 `train.quick_eval` 子集定义（当前实现取"前 n 段"，需改为显式序列列表）。

### 阶段 B — 诊断跑与 Kill 判据（半天，单卡）

`limit_seqs` 小规模、200–500 步，**必须全部满足才允许进入阶段 F**：

| 指标 | 判据 | 现状参照 |
| --- | --- | --- |
| `m_frac` | < 0.3 | 修复后 0.0 |
| `alpha_mean` | < 0.3 | 0.119 |
| `recon_valid_frac` | > 0.05 且全程无 0 | 0.950 |
| `tau_scale_ratio`（**实现值**，非 τ/\|f\|） | ≥ 3 | 待建 |
| `bg_resid` ↓ 且 `resid_scr` **显著离开 1.0** | — | 1.011 / 0.999 → **Kill 判据** |

**Kill 判据的语义**：若 5k 步内 `resid_scr` 仍贴在 1.0 附近，说明"背景吸收背景"这一核心假设在 ITTD 上不产生信号，应停止加码 DSLD，转为诚实降级（编码器 + 时序聚合）基线。这是本项目最重要的一条止损线。

### 阶段 C — ITTD 专用机制（1–2 天）

| # | 动作 | 依据 | 出口 |
| --- | --- | --- | --- |
| C1 | **消费配准质量**：把 `reg['failed']`/`rmse`（**已加载却未使用**）与逐帧 `quality` 送进核心；失败帧**冻结 `h_B`**、按 rmse 放大残差容差 | 287 失败帧 + 2,150 FM 帧；§1.4 显示 FM 主导段在 train-int 有 5 段 | 失败帧上的虚警计数单独可报 |
| C2 | **残差按局部对比度归一化**：`r = (x−ŷ_B)/(\|∇ŷ_B\|+ε)`，用于门控与 `L_recon` | 配准残余在强边缘产生最大绝对残差 → `strong_clutter` 21 段的虚警大头 | `strong_clutter` 子集 F_a 相对阶段 B 下降 |
| C3 | **尺度选择性抑制**：σ≈3px 与 σ≈12px 双尺度残差，门控对大尺度响应做**减法** | 行人/电瓶车无标注（48/87 段），时序残差器必然报为虚警（每个 −2） | `distractor_present` 子集虚警率单独可报 |

C3 是**必须做**的：这是"液态核单独无法达成 F_a 目标"的直接对冲，也是报告里必须写明的诚实边界。

### 阶段 D — 补分母与官方对拍（与应用无关，可并行启动）

| # | 动作 | 为什么现在必须做 |

| D2 | **两基线训到收敛**（MSHNet、T-MSD3D） | ITTD **无任何公开榜单**，所以官方分的"最优对比基线"只能自建——**分母缺了，后面所有 F_a 结论都无法宣判** |
| D3 | 统一主口径：中心点官方分 vs 框级 IoU-F1 并列报表 | 同一模型已出现"官方记 243 命中而 IoU≥0.5 的 tp=0"的矛盾 |

### 阶段 E — 并行化重排（在 Gate 训练**之前**或并行）

把逐帧 Python 循环换成窗口内并行求解（`cumsum` 闭式扫描 + max-plus 掩码扫描），把 32 次串行小算子变成 4 次批量大算子。现状 `2.96 GFLOPs/帧 ÷ 3.1 FPS ≈ 9.2 GFLOP/s`（约 0.06% 利用率）说明是**延迟受限**，量级提升空间大（须实测）。动机：50k 步 Gate 在 3.1 FPS 下日历成本不可接受，**这件事的优先级高于精度调优**。

> 前置：A1 的显式泄漏形式正是并行化的前提（线性递推可扫描）。**A1 与 E 是同一项投资的两半。**

## 3. 明确不做（本阶段）

| 不做 | 理由 |

| 不调超参追指标 | 机制未证伪前调参只是拟合噪声 |

## 4. 云端处置（回应 §2.1 的建议，我的结论）

回应文档判断"云端 A10 上 9856f8c 的训练从第 1 步即处于窒息态，已产出结果不可用于 M3 Gate，建议停掉、pull 后从零重启"——**同意，但需补两点**：
