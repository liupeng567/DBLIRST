## 0. 结论摘要

现有实现**忠实实现了 CfC 的 Default 模式**；而"液态时间常数"的语义只存在于同篇论文的 **Pure / LTC 分支**。因此问题不是"实现写错了"，而是**选错了分支**。

修复路径 = ① 换分支（τ 进指数、加性正定有界速率）＋ ② 窗口内并行化（同时解决 3.1 FPS）＋ ③ 四个 ITTD 专用机制（配准质量消费、残差对比度归一化、尺度选择性抑制、有界保持项）。

**三条检索结论直接改变依据结构**：

1. ✅ 参考实现 `ncps` 的时间处理是 `σ(t_a·t + t_b)`，其中 **`t_a` 是自由无约束参数**——即连参考实现都不**结构性**保证 τ。
2. ✅ `ncps` 本身的 CfC/LTC 实现就是**逐帧 Python 循环**，与本次性能问题同源；不能指望它作为快速路径。
3. ✅ ITTD **没有任何公开榜单数字**——这使"官方分超过最优对比多帧基线"只能靠**自建基线**成立，从而把 M2 基线缺口从"数据缺失"升级为"整个对比基准缺失"。

## 1. 依据 A：CfC 的时间常数到底在哪里

### 1.1 论文原文（✅ 已核实）

[Closed-form Continuous-time Neural Networks](https://ar5iv.labs.arxiv.org/html/2106.13898)（Hasani et al., *Nature Machine Intelligence* 2022；[期刊页](https://www.nature.com/articles/s42256-022-00556-7)）：

```
dx/dt = −(w_τ + f(x,I,θ))·x(t) + A·f(x,I,θ)                      (1)
x(t)  = (x₀ − A)·e^{−[w_τ + f(I(t),θ)]·t}·f(−I(t),θ) + A         (2, 定理1)
x̃(t) = (x(0) − A)·e^{−[w_τ·t + f(I(t))·t]}·f(−I(t)) + A          (8, 引理1)
|x(t) − x̃(t)| ≤ |x(0) − A|·e^{−w_τ·t}
```

原文对 `f` 的要求是"**Lipschitz continuous, positive, monotonically increasing, and bounded**"；对 `w_τ` 的表述是"**a time-constant parameter vector**"、"**positively defined**"。

整理成"保留项 + 吸引子"形式：

```
x(t) = x(0)·a + A·(1−a),   a = e^{−[w_τ + f(I)]t}·f(−I(t)) ∈ (0,1)
```

**要点**：`w_τ` 在**指数**内，`f(I)` 是**加性、正定、有界**的速率增量；有效时间常数 `τ_eff = 1/(w_τ + f(I))`，**输入只能让状态变快，不能变慢**。这就是"液态"的定义。

### 1.2 参考实现的实际做法（✅ 已核实）

[ncps torch CfC 源码](https://ncps.readthedocs.io/en/latest/_modules/ncps/torch/cfc.html)、[tf 版](https://ncps.readthedocs.io/en/latest/_modules/ncps/tf/cfc.html)：默认模式的门控是 `σ(t_a·ts + t_b)`，其中 `t_a`/`t_b` 是作用在 `[input, h]` 上的**普通 `nn.Linear`（带偏置）**——`t_a` **既无正定性约束、也无 softplus**，且 **sigmoid 的自变量未取负**。默认 `ts = 1.0`，于是该门控退化为一个**纯学出来的标量**：既没有时间语义，也没有任何结构性时间常数。

（`pure` 模式才是带约束的版本：`h = a − a·exp(−t·(|w_τ| + |ff1|))·ff1`，`|w_τ|` 即"正定有界"的参数化；另有 `no_gate` 模式。**`mixed_memory` 亦已核实存在**：`CfC(..., mixed_memory=True)` 用 `MixedMemoryRNN`（LSTM）包住 CfC 单元——这正是方案 §4.9-1 登记的"mmRNN 混合状态"退路，可选可查。）

[ncps Rust 移植的源码文档](https://docs.rs/ncps/latest/src/ncps/cells/mod.rs.html)则把两种模式并列写明：

| 模式 | 公式 | 文档原话 |
| --- | --- | --- |
| Default（其推荐） | `h = tanh(ff1)×(1−σ(t)) + tanh(ff2)×σ(t)` | "**Gated interpolation between two feedforward paths**" |
| Pure | `h = a − a×exp(−t×(\|w_τ\| + \|ff1\|))×ff1` | "**Direct ODE solution** without gating" |

**判定**：项目现实现（[`liquid_core.py:95`](../dsld/models/liquid_core.py) `h' = p·g + (1−p)·m`，`g`/`m` 均为 `[h,x]` 的 1×1 卷积输出）就是 Default 模式——**两个操作数都不是上一帧隐状态**，与 `ncps` 文档对 Default 的描述逐字吻合。方案 §4.2 声称的"硬约束保证双状态时间尺度分立假设不被训练破坏"，在这条分支上**无法兑现**。

## 4. 方案

### 4.0 不变量 0：把约束加在**实现出来的保留系数**上，而不是加在隐参数上

这是全案的判据，先立此条再谈方程。设更新为 `h' = a·h + (1−a)·c`（`a` 为保留系数），则：

| 参数化 | `a` 的可达范围 | τ 是否被结构性约束 |
| --- | --- | --- |
| 现状：`clamp(θ_τ)`，`p = σ(−f·dt/τ)` | `a = 1−p = σ(+f·dt/τ)`，**任意** (0,1)（`f` 自由） | ❌ clip 只约束隐参数 θ_τ，效果被 `f` 抵消 |
| `ncps` 默认：`σ(t_a·ts + t_b)` | 任意 (0,1) | ❌ 无正定性约束、无时间语义 |
| 建议：`a = σ(−softplus(w)·dt/τ)`，**τ 固定** | 仍为任意 (0,1)（`softplus(w)` 可任意补偿） | ❌ 仍然抵消 |
| **本方案：`a = exp(−Δt·λ)`，`λ = clamp(w_base + g·σ(·), λ_min, λ_max)`** | **`[exp(−λ_max), exp(−λ_min)]`，被构造性限制** | ✅ **实现的保留系数被夹在固定区间内** |

**结论**：`exp` 与 `σ` 的函数形式是次要的；**决定性的是"实现出来的 `a` 是否被构造性夹住"**。只要 `λ`（或等价的 `1/τ`）被硬 clip 在**值域**上，`a` 的区间就不受网络自由度影响，两通道的尺度分离才是**结构性**而非涌现性。反之，任何只 clip 隐参数、却让自由乘子/自由线性层去乘除 τ 的写法，都无法兑现"分立由结构保证"。

> 这也是为什么 `f_bound` 是假解：它限制的是自由乘子的幅值，而没有把 `a` 夹住——小则让 `a→0.5`（退化为前馈），大则不生效。

### 4.1 状态方程

```
# 速率：加性、正定、有界（论文式(1) 的直译）
λ_B(t) = w_B + g_B·σ(W_B·x_t)                 # 背景：输入只能加速，不能减速
λ_T(t) = w_T + g_T·σ(W_T·x_t) − κ·α_{t−1}      # 目标：允许"确认后减速"（保持项）
λ      = clamp(λ, λ_min, λ_max)                # 结构先验：实现出来的 τ 硬约束在此生效
a(t)   = exp(−Δt·λ(t))                        # ★ 保留系数：τ 在指数里
c(t)   = tanh(U·x_t + b)                      # 写候选（不含 h → 见 §4.3）
h(t)   = a(t) ⊙ h(t−1) + (1 − a(t)) ⊙ c(t)    # ★ 上一帧状态是显式保留项
ŷ_B(t) = V·h_B(t)
```

对应关系：`p ≡ (1−a)`，"p→0 保持历史"由**保留项即 `h` 本身**结构性保证；原 `m` 分支的角色降为候选的偏置/精修项（可保留为 `c = tanh(U x + m_scale·M x)`，三头与 FiLM 全保留、无死参数）。

### 4.2 数值与"构造上分立"

方案给的 τ_B∈[16,256] 与 τ_T∈[2,16] **在上界 16 处重叠**，本身不保证分立。改为两段**不相交**区间：

| 量 | 背景通道 | 目标通道 |
| --- | --- | --- |
| 目标 τ_eff 区间 | **[24, 192]** | **[2, 8]** |
| λ 区间 | [1/192, 1/24] = [0.00521, 0.04167] | [1/8, 1/2] = [0.125, 0.5] |
| 参数化 | `w_B = 1/192`，`g_B = 1/24 − 1/192 = 0.03646` | `w_T = 1/6`，`g_T = 1/3` |
| 初始 λ（目标 τ） | 1/48 = 0.02083 → 偏置 `logit(0.4286) = −0.288` | 1/6 = 0.1667 → 偏置 `logit(0) = 0` |
| 保持项 | 无 | `κ = κ_max·σ(θ_κ)`，`κ_max = 0.5`，λ 下限 1/8 → τ_T 最多到 8 |
| 半衰期 `τ·ln2` | 16.6 – 133 帧 | 1.4 – 5.5 帧 |
| 单帧 `a = exp(−1/τ)` | 0.9592 – 0.99480 | 0.6065 – 0.8825 |

**由此得到一条可证明的不变量**：`τ_eff_B / τ_eff_T ≥ 24/8 = 3`，**构造上成立**，不依赖训练涌现。θ_λ 的硬 clip 施加在 **λ 域**（`log(1/τ_max) ≤ θ_λ ≤ log(1/τ_min)`）——方案宣称的"硬约束保证分立"**第一次真正成立**。

### 4.3 ★ 窗口内并行化（同时解决 3.1 FPS）

因 §4.1 中 `a` 与 `c` **只依赖 `x_t`**，递推对 `h` 是**线性**的，T=32 整窗有闭式解：

```
h_t = (Π_{j≤t} a_j)·h_0 + Σ_{k≤t} (Π_{k<j≤t} a_j)·(1−a_k)·c_k
```

工程实现（全部 log 域 `cumsum`）：

```
L_t = Σ_{j≤t} log a_j                                    # 一次 cumsum
h_t = exp(L_t)·[ h_0 + Σ_{k≤t} exp(−L_k)·(1−a_k)·c_k ]    # 又一次 cumsum
```

**数值安全性（手算，待实测）**：

| 通道 | a 区间 | `a^32` 最坏值 | fp32 结论 |
| --- | --- | --- | --- |
| 背景 | [0.9592, 0.9948] | `exp(−32/24) = 0.264` | ✅ 无需归一化 |
| 目标 | [0.6065, 0.8825] | `exp(−16) = 1.1e−7` | ✅ 远高于 fp32 最小正规数 1.2e−38 |

反馈掩码同样可并行（max-plus 扫描）：

```
M_t = max( dilate(P_t), γ·M_{t−1} )
  ⟹  log M_t = cummax_k[ log dilate(P_k) + k·log(1/γ) ] − t·log(1/γ)
```

**收益**：把 32 次串行小算子（3 头 × 2 通道 × 32 帧）换成 **4 次批量大算子** + 若干 elementwise 扫描。依据：当前 `2.96 GFLOPs/帧 ÷ 3.1 FPS ≈ 9.2 GFLOP/s`，相对 4060 Laptop bf16 峰值（~15 TFLOP/s 量级）**仅约 0.06%** —— 典型**启动/延迟受限**。故量级提升空间在 10–100×，**但必须实测确认**（本方案唯一的强预期式断言）。

**旁证与先例**：

- 检索确认 **`ncps` 自身的 [CfC](https://ncps.readthedocs.io/en/latest/_modules/ncps/torch/cfc.html) 与 [LTC](https://ncps.readthedocs.io/en/latest/_modules/ncps/torch/ltc.html) 实现都是逐帧 Python 循环** —— 逐帧循环是该家族的**共性问题**，不是本项目实现缺陷；也说明"照抄参考实现"不会带来速度。
- 并行扫描是通用解法：线性高斯 SSM 的并行滤波/平滑（[DynaMax](https://probml.github.io/dynamax/notebooks/linear_gaussian_ssm/lgssm_parallel_inference.html)）、独立实现包 [`accelerated-scan`](https://pypi.org/project/accelerated-scan/)、以及 S4→Mamba 一系把 scan 作为核心算子（[SSM 演化综述](https://www.semanticscholar.org/reader/124374e44e4eb63248d303c2623671626ffc7354)）。
- **关键帧 + 传播**是视频高效推理的成熟范式（[ECCV 2022](https://www.ecva.net/papers/eccv_2022/papers_ECCV/papers/136700296.pdf)）；IRSTD 侧的实例是 RFR 的**金字塔可变形对齐（PDA）+ 循环传播**（[arXiv:2409.12448](https://arxiv.org/html/2409.12448v3)）——见 §8.2。
- **IRSTD 领域内未检索到**"把递推降分辨率跑"或"分块/扫描式 IRSTD 递推"的工作（○），故本方案 §4.3 属**领域内首次尝试**，须自证。
- 边缘端参照（◐ 单一来源、片段级）：轻量 Mamba 变体 LIR-Mamba 报告 **Jetson Orin 上 61.3 FPS**（*Scientific Reports*）。当前 3.1 FPS 与之相差约 20×，这是"边缘部署候选"这条要求的现实标尺。

**代价与对冲**：`a` 不看 `h`，丢掉了 LTC 的"状态相关时间常数"。对冲 = 方案的**双尺度**：主尺度 stride-2 走并行扫描；**区域尺度 stride-8（60×80）跑小规模、状态相关的串行核**（串行成本可忽略），输出上采样后作为主尺度门控/上下文。双尺度由此从"精度特性"升级为"**可部署性的必要结构**"。

### 4.4 四个 ITTD 专用机制

**M1. 消费配准质量（几乎零成本）**
[`IttdWindows`](../dsld/data/ittd_window_dataset.py) 已执行 `reg = dict(np.load('reg.npz'))`，但**只用于对齐，`failed`/`rmse` 被加载却从未消费**。

- 配准失败帧：`h_B` **冻结**（不吸收错误的背景），残差容差按 `rmse` 放大；
- FM 回退帧（2,150 帧）：容差按 `1−corr` 插值放大。

**M2. 残差按局部对比度归一化（直击 −2 分大头）**

```
r_t = (x_t − ŷ_B(t)) / (|∇ŷ_B|_local + ε)      # 或除以预测局部标准差
```

配准残余在强边缘处产生最大绝对残差，是已配准 LWIR 背景减除中虚警的主导来源。现实现用裸 `|x−ŷ_B|` 进门控与 `L_recon`（[liquid_core.py](../dsld/models/liquid_core.py)、[losses.py:141](../dsld/train/losses.py)），强杂波段必然被边缘淹没。

**M3. 尺度选择性抑制（对冲无标注干扰目标）**
行人/电瓶车与 5–25 px 目标**在尺度上可分离**（需用现成 [probe_distractors.py](../scripts/probe_distractors.py) 先验证）。做法：在 σ≈3 px 与 σ≈12 px 两个尺度各算残差（小核 max-pool 差即可），门控 α 对**大尺度响应做减法**。这是方案 10.7 ROI 判别头到位前的廉价替代，也是必须写进报告的**诚实边界**。

**M4. 静态/遮挡的保持项有界化**
`λ_T − κ·α_{t−1}`，`κ ≤ 0.5`，λ 下限 1/8。效果：确认后 τ_T 从 6 最多延到 8 帧（与方案"约 10 帧"同量级），**不可能越出结构区间** —— 区别于当前"减 `β·α_prev` 到自由门控上、上界无保证"。

### 4.5 损失

- `L_seg`：保留；监督施加在**归一化后**的残差通路上（与 M2 一致）；
- `L_recon`：保留"掩码外 L1"，但（a）加有效像素守卫（禁止静默归零），（b）目标改为**低通背景**而非原始帧（慢通道的任务是预测背景，不是预测含目标的帧）；
- `L_dec`：改为**范数下限 + 软正交**，使 `h≡0` 必然产生正损失。可用的成熟工具（✅ 文献支持）：
  - **VICReg** 的 variance + covariance 项（防止维度坍缩）；
  - **Barlow Twins** 的冗余削减（互相关矩阵趋近单位阵）；
  - 正交性正则（NeurIPS 2024, [arXiv:2411.00392](https://arxiv.org/abs/2411.00392)）；
  - 维度坍缩现象的系统描述见 [Jing et al., arXiv:2110.09348](https://arxiv.org/abs/2110.09348)。

### 4.6 Gate：只测实现出来的动力学

| 判据 | 阈值 | 为什么可证伪 |
| --- | --- | --- |
| `τ_eff_B / τ_eff_T` | ≥ 3 | 构造上成立；若训练压下去，说明调制/保持顶到 clip 边界（须同时上报边界占用率） |

| `recon_valid_frac > 5%` | 全程 | 防监督静默 |

## 8. 文献定位：本方案在时序 IRSTD 谱系中的位置

### 8.1 已验证的机制先例（◐ 来源为检索汇总，未逐篇精读）

| 工作 | 机制 | 与本方案的关系 |
| --- | --- | --- |
| **STDMANet** | 时空差分注意力 | 属**时序融合**，无显式慢背景/快残差分立 |
| **SSTNet**（TGRS 2024） | 跨切片 ConvLSTM | 同上；可作为 M2 的**时序基线候选**（优于项目自研 T-MSD3D） |
| **RFR** | 循环精修 + 金字塔可变形对齐 + TSFM | 同上；其"可变形对齐"与项目 M1 的桥矩阵思想同源 |
| **MiM-ISTD** | Mamba-in-Mamba | 状态空间路线；与 §4.3 的并行扫描思路同族 |

**结论**：这些代表工作**都是时序融合**，而"**显式慢背景状态 + 快残差状态 + 输入流分离**"这一框架**未见先例**——即：

- 好消息：**双状态框架是真实的空白**，叙事有立足点；
- 坏消息：**没有可照抄的配方**，机制必须自证（这更凸显阶段 2 诊断跑与 Kill 判据的必要性）。

**战略含义（本次检索最有价值的一条）**：论文叙事不应落在"我们用了 CfC / 液态网络"（这是实现细节，且参考实现本身不保证时间常数），而应落在

> **"背景更新污染"（target absorbed into the background model / ghosting）在递归式背景建模中是公认失效模式，但在红外小目标领域没有任何定量消融——本项目用"检测反馈门控的背景更新"给出该领域的首次定量证据。**

支撑这一落点的检索结论：

- 该失效模式在 ViBe 类递归背景减除中被明确命名与讨论（随机替换更新策略导致的 ghost / 目标空洞化），见 [ViBe 综述](https://hal.science/hal-04497901v1/file/article_lr%20%281%29.pdf)、[背景减除综述](https://escholarship.mcgill.ca/downloads/6d5701559?locale=en)；
- 工程界的对策与项目的反馈掩码**同源**：选择性/保守更新（只在判为背景处更新、检测掩码内冻结）、ViBe 式随机子采样、样本/词共识模型（[PAWCS](https://ieeexplore.ieee.org/document/7530875)）以"背景词历史"替代滑动均值，使慢速入侵者无法迅速主导模型；
- **但红外小目标领域内未检索到该失效模式的定量消融**（○）——空缺即贡献点；
- 因此 §4.4-M1（配准质量门控更新）与反馈掩码应当被当作**一等贡献**来设计与消融（掩码上界 `m_max`、`α_th` 与门控初始化的联合设计即是其自变量），而不是"实现细节"。

### 8.2 可直接借用的成熟工具

- **坍缩防治**：VICReg（variance + covariance）与 Barlow Twins（冗余削减 / 互相关矩阵趋近单位阵）是经验支持的标准组合。特别注意：**VICReg 的 variance floor 正是本项目 `cos²` 所缺的那一项**——`cos²` 只惩罚"两状态对齐"，对"任一状态塌缩"完全无约束（`h≡0` 时 `cos²=0`）。维度坍缩即便在完全坍缩被阻止时也仍然存在（[Jing et al., arXiv:2110.09348](https://ar5iv.labs.arxiv.org/html/2110.09348)）。
- **运动补偿的学习式替代**：RFR 的**金字塔可变形对齐（PDA）**做隐式运动补偿 + 特征循环传播（[arXiv:2409.12448](https://arxiv.org/html/2409.12448v3)），是 IRSTD 侧最接近"预测背景再精修"的公开工作。**对本项目的直接启发**：M1 的仿射配准只能消掉全局运动，残余的非刚性/视差形变正是 §4.4-M2 要处理的虚警来源；PDA 式**可学习对齐**可作为 M1 之上的第二级补偿——这也是把"配准质量消费"升级为"配准残差学习"的路径。
- **并行状态空间**：[ThetaScan: Scan-Parallel Nonlinear Memory](https://github.com/aim-do/thetascan/blob/1302bff8a6423261f3178f37354636aeeb464047/paper/ThetaScan-Scan-Parallel-Nonlinear-Memory.pdf) 试图在保留状态相关性的同时并行化。**未核实其可复现性**（○），仅列为后续选项；若成立，可去掉 §4.3 的"`a` 不看 `h`"这一代价。
- **时间处理反例**：`ncps` 默认模式的 `σ(t_a·ts + t_b)`（自由线性层、无正定约束、自变量不取负）——本方案要**避免**的模式。

### 8.3 未核实的项（明确列出，不编造）

1. **ITTD 无公开榜单数字**（负面结论已核实）；因此方案可行性只能由机制正确性论证。
2. 上述 8.1 各工作的**具体指标数字未核实**，不得引用为对比基线。
3. "**零初始化硬阈值门导致掩码饱和**"这一具体病理**未检索到文献支持**（○）。它在本项目中是**实测发现**（`alpha_mean=0.5003` 而 `alpha_frac_high=0.94`），应作为**工程贡献/教训**写入报告，而非引用他人结论。

## 9. 诚实边界

1. **液态核单独无法达成 F_a 目标**。48/87 段含**无标注**的行人/电瓶车干扰目标，时序残差检测器会把它们全部报为虚警（各 −2 分）。这不是调参可解决，必须靠尺度先验（M3）或方案 10.7 的判别头。任何"F_a 降 10×"的承诺都必须把该依赖写进结论。
2. **并行化的代价是真实的**：`a` 不看 `h` 会使时间常数与状态解耦。双尺度是对冲，但属**设计判断**，未被本项目验证。
3. **所有手算数字未经执行验证**（2.11 GFLOPs、`a^32`、9.2 GFLOP/s 利用率、参数量、区间端点）。本机 PowerShell 被 DSH 沙箱 ACL 阻断，未跑任何测试或测量。
4. 方案 §4.2 的 τ 区间与本文 §4.2 的建议区间**不一致**（方案 [2,16]×[16,256] 在上界重叠；本文建议 [2,8]×[24,192]）。这是**需要项目负责人决策的规格变更**，并应一并更新方案文本与消融定义。
5. 本文**只新增文档，未改动任何现有代码**。
