## 3 P0 Gate 逐条作答

### ① 对齐单测（恒等 / 整数平移双向 / 桥跨边界）

- 桥跨边界对齐回归 + NaN 桥续链：`tests/test_register.py::test_align_to_anchor_nan_bridge_continues_chain`、`::test_bridge_cross_boundary_alignment`（HEAD 原式，未改语义）。
- GT 锚点对齐**双向**：`test_gt_mask_anchor_identity_and_integer_translation_both_ways`（恒等面积 72 精确、整数平移 (5,3)/(−4,−6)/(0,7) 中心回收 ≤0.6px）+ `test_gt_mask_anchor_direction_is_falsified`（漏 `WARP_INVERSE_MAP` 的错误方向必须与 `warp_frame` 输出**不同治**，实测亮块覆盖率 >0.9 vs <0.1）。
- 帧与掩码同治：`test_synthetic_window_frames_and_gt_move_together` 逐帧断言掩码中心 = 解析位移 −(Δt−Δ0)，且掩码覆盖处像素均值 >0.75，另加"整体平移 3px"对照必须掉 >0.2（防恒真断言）。
- 真实 reg.npz 交叉验证：`test_anchor_rect_matches_pixel_warp_on_real_reg`（seq 21 一窗内 ≥5 个框，解析外接矩形 vs 像素 warp 结果 ≤1.5px）。

**这组测试在编写期就抓出 3 个真实实现错误**：`box_fill` 的 `frame` 参数 0/1-based 混用（会让 GT 掩码整窗丢失）、面积容差过松（1px 口径错误测不出）、框外像素断言写错。

### ② 裁剪保完整约束（§4.7）

约束实现为**可行区间直接采样**（不是"随机裁剪后拒绝"）：先算窗内每条轨迹在锚点系的并集矩形，再解出满足 `y0 ≤ y1−3` 且 `y0+h ≥ y2+3` 的起点区间，在区间内均匀取值——因此"≥1 完整 GT 框含 3px 边距"是构造成立，不是概率成立。四档记账：

| 档 | 含义 | 快评子集 12 窗 | train-int 前 4 段 24 样（单测） |
| --- | --- | --- | --- |
| `all_tracks` | 全部轨迹整窗轨迹完整（最强） | 9 | 17 |
| `one_track` | ≥1 条轨迹整窗完整 | 3 | 5 |
| `one_frame` | 仅保证 ≥1 个 (轨迹,帧) 框完整 | 0 | 2 |
| `negative` | 窗内无 GT（合法负样本） | 0 | 0 |
| `fallback` | 连单帧框都装不下 → **换窗重采** | — | 3 次触发，重采后 0 个窗以 fallback 交回 |

单测 `test_crop_never_returns_fallback_on_real_cache` 用**连通域口径独立复核**（不复用数据集的区间算术）：24/24 窗均存在含 3px 边距的完整框；GT 贴边率 0.08。合成用例 `test_crop_prefers_all_tracks_then_one_track` 给出解析真值（纵贯全幅的长轨迹必然不可行 → 退到 one_track 并如实标 `gt_clipped=True`）。

`reports/m3/p0_seq{0021_s007, 0038_s000, 0023_s001}.png`（全部 12 张见 `reports/m3/`），每张 5 联：对齐后 t=0/16/31（GT 轮廓叠加）、窗内逐像素时序 σ（灰度级）、合成注入 footprint（同 seed 关注入重放取差）。人工判读结论：

- **seq 21（强杂波、KLT 31/32）**：t=0→31 结构边缘无重影，3 个 GT 框稳定压在亮目标上；时序 σ 中位 0.00 灰度级（背景在锚点系近乎冻结），仅注入点与目标自身留下亮点；注入点距最近 GT 膨胀区 57px（`落 teacher 区 0 px / 落 target 区 0 px`）。

## 5 需裁决事项（P1 开工前应定，按影响排序）

**F1 ITTD 缓存每 3 帧有 1 个字节级重复帧（12 段实测：83/249 = 33.3%，游程 ≤2–3；seq 44 为 26.9%）。**
即 T=32 的窗内只有 ~22 个不同帧，有效内容帧率 ≈ 33–37 Hz 而非标称 50 Hz。

处置口径（2026-10-08 复核后**更正**本报告初稿的推荐）：

- 初稿推荐"核心吃 Δt 序列、重复帧 Δt=0 ⇒ 状态完全保持"，并称之为 CfC 的本行。**这个论证是错的**：
  重复帧是**过期的测量**，不是**暂停的时间**——传感器仍以 20 ms 定间隔出帧，背景的 ODE 在该 20 ms 内
  照样在泄漏。取 Δt=0 等于把模型改写到"内容时间"轴上，其后果是 τ 的物理单位从"秒"变成"第几个不同帧"，
  而**推理端一旦遇到无重复的流（M6 的 IRDST-Real、实采 50 Hz）就会得到另一套动力学**——
  训练/推理口径分叉，正是 L4 那一类"静默毒化"。
- 因此推荐 **A：Δt ≡ 1（容器时间）**，把重复帧如实当作"同一证据连续两次"，动力学单位仍是秒，
  与任何帧率的推理流天然一致。代价只是：① 快通道 1/3 的步进无新证据（τ_T 在"内容单位"下等效 1.5×，
  报告 τ 时**同时**给容器单位与内容单位两个数）；② §2.6 的"帧复制 p=0.3"增强与数据本身重复，
  其增量作用被高估（保留无害，但消融 a7/难例统计要按"不同帧"分层）。
- 若仍要试 C（内容时间），必须先解决推理端同治：滑窗也要按"不同帧"取样并携带内容时间戳，
  否则 C 不可选。**B（数据集侧去重）与 C 同病**，且额外破坏 reg.npz 帧号与窗口的对应关系。

未决：等用户按更正后的机制重新裁决（初稿选择为 C，选择依据是初稿的错误论证）。


**F2 判据 ① 的"背景稳定度 ≤ M1 P95（3.39）"口径不可直接比。** M1 的 3.39 是**相邻帧对**残差；M3 慢通道关心的是**锚点系长滞后**残差（实测 lag31 中位 4.39 > 3.39，而 lag1 中位 0.45 ≪ 3.39）。且 lag1 本身被 F1 的 1/3 重复帧压低。建议把判据 ① 改写为"按滞后分位给带"（如 lag1 ≤ 3.39 且 lag31 ≤ 2×M1 P95，超带域单列），否则该判据在两个口径下一个必过、一个必挂——正是 L2"不可能失败指标"的镜像。

**F3 FM 域在近静止场景上过校正。** seq 68：配准后 lag31 = 2.91–3.17，**不配准只有 2.37–2.46**（配准反而变差）；seq 67：4.93–7.23 vs 6.57–8.69（改善仅 1.2–1.3×，且 motion_blur=True）。判据 ① 的"该域窗口剔除并单列"分支很可能被触发，需要预先决定：FM 域窗口是剔除、还是降级为"时序主张只覆盖 KLT 达标域"。

**F4 §4.7 裁剪约束的强度选择。** 真实数据上"全部轨迹整窗完整"只成立 9/12（快评子集）～17/24（train-int 抽样）——横跨全幅的长轨迹物理上装不下。现状是"≥1 条整窗完整 + 其余如实记账"。可选：保持（现状，推荐）／改为"最大化完整轨迹数"（每窗枚举候选偏移取最优，成本 +约 10ms/窗）／放宽到"单帧完整"（会引入边界漏检偏差）。
