## 一、方案让 M3 承担的原定目标（账本口径）

| 目标 | 出处 | 验收阈值 |
| --- | --- | --- |
| 同 P_d 下虚警数量级下降 | 根方案文首:13、§8.5 G-虚警 | P_d≥0.90 时 F_a ≤ 单帧基线 ×0.1（§9.2 M4 行写 ≥10×） |

机理上这些收益被明确归因于四个构件：**三重串联一致性门控**（§5.1–5.3）、**抑制显著图 + 自适应阈值判决链**（§5.3）、**检测-跟踪一体化**（h_T 驱动关联门 + 航迹 M-of-N 确认，§6.2–6.4）、**ROI 干扰判别头**（§10.7）。

## 二、代码实际覆盖了什么（可核验）

`dsld/models/liquid_core.py` 的 λ 域指数泄漏重写本身是干净的：终 clamp 使 a∈(0,1)、`tanh` 候选使 ‖h‖∞≤1、τ 区间（B [24,192] / T [2,8]）构造性不相交，反馈掩码有 `m_max=0.8` 硬上界，`recon_loss` 的窒息拦截改为 strict 抛错，`decouple_loss` 补了范数下限——独立评审提的三个致命伤在结构上确实被堵住。

但**承担虚警收益的四个机理构件没有一个在代码里**：

1. **三重门控缺失**。`liquid_core.py:239` 只有 `gate_head = Conv2d(c_in+c_h, 1, 1)` 吃 `[x_res, h_T]`（注释自认"M3 临时门控（M4 换三重门控）"）。§5.1 的 e_B 的 σ̂_B EMA、r_T 的 γ-EMA、LR 的 ŷ_T/σ̂_T 三件全无。**r_T 恰是报告第 4 章机理（"孤立瞬现 → 压制"）唯一的落地支路**，缺它之后 α 与单帧显著性在输入信息上同源；消融 (c)"有无一致性门控"无从做起。
2. **判决链不含门控**。全仓检索 `alpha`/`h_t` 的下游消费，只命中 `trainer.py:350`（L_dec）与 `:452`（监控落盘）。推理走 `infer_seq.py:99-101` 的 `sigmoid(logits)` → `mask_to_boxes(固定阈值)`。`configs/dsld_core.yaml:80` 的 `infer.threshold.k=3.0`（§5.3 的 μ+kσ 自适应阈值）**无任何消费者**。
3. **一体化未实现**。`tracker.py:7-8` 明写"不做 M-of-N 确认过滤、不按航迹长度删输出"，用常数速度贪心关联，不读 h_T。§6.2 tentative/confirmed/lost 状态机、§6.3 `hT_extrap`、§6.4 航迹质量分——`IDsw|idf1|tentative|kalman|centerness|box_head` 全部零命中。**报告批评的"检测跟踪分阶段处理造成信息丢失"，正是当前实现本身。**
4. **损失六分量只落三个**（`trainer.py:336` 注释自陈）：L_cons④（时序一致性先验显式注入）、L_box⑥（v1.4 检测主路框回归）、L_aux⑤（SAM 实例掩码已缓存进 `masks.npz` 但未被消费）均缺。§7.2 阶段 A 预训练（IRDST-Sim/SIATD）无数据集实现，§7.3 难例挖掘无脚本，§7.4 分层采样/SCR curriculum 无，§7.5 EMA 无。

## 三、两个会决定成败的结构问题（本次审核新发现）

### ① τ_B 与 T=32 窗口在算术上互相否证

状态每窗从 0 冷启动且绝不跨窗（`liquid_core.py:293-294` 置零；`infer_seq.py:98` 每窗独立前向；训练侧 `IttdWindows` 每样本独立窗，`detach_every=0`）。按 a=exp(−1/τ) 实测：

| τ_B | 32 帧窗口末 h_B 达稳态幅度 | warmup 结束（第 8 帧） |
| --- | --- | --- |
| 24 | 0.736 | 0.283 |
| 48（init/中位） | **0.487** | **0.154** |
| 192 | 0.154 | 0.041 |

即"背景通道覆盖数十至上百帧长期记忆"这一主张（报告 §5.2）在本配置下从未被真正执行，梯度也从未观测到其稳态行为；L_recon 最省力的降损失路径是把编码器输出压成时平坦，而非学出长记忆背景。推论：报告宣称"连续时间 ⇒ 无需纠结时间窗大小"在实现中被还原为**固定 32 帧窗 + 8 帧 warmup**，且滑窗 stride=24 使约一半帧的判决落在慢通道未收敛段。`tau_scale_ratio ≥ 3` 这条 Gate 即使通过，也只证明参数化分立，不证明慢通道在做背景记忆。

（注：`scene_stats` 含帧序归一化 t/T，FiLM 可学到一条窗口索引相关的斜坡补偿，故此项非"必然失效"，而是"慢通道的长 τ 自由度不可观测、其声称功能未被证成"。）

### ② 未标注动目标构成 F_a 地板

`reports/m0/seg_precheck_report.md` 干扰探针：v9 段 3 个 GT 框对应 **18 个框外运动区**；行人/电瓶车等"有像素、无框、无 ID"，官方口径每个未匹配判 −2 分。这类干扰**恰恰时序一致**，用"像不像持续运动目标"作判据在机理上无法拒绝，只能靠 §10.7 ROI 判别头与阶段 C3 尺度选择性抑制——两者均未实现，而 48/87 段含此类干扰。这决定了"同 P_d 下 F_a 降一个数量级"在任务级指标上可能被非杂波源的虚警封顶。

### 其余已登记或未登记的缺陷

- 掩码锁定模式（作者已登记，`M3_核心动力学返工报告.md:90`）：静态热点被高 α 打码 → 背景通道不学它 → 残差自持，方向正好打在 ITTD 主虚警源"强红外辐射地物"上，M4 对冲件未落地。
- 快通道无"沿轨迹保持"：每步仅 `dw_ctx` 3×3 视野（±1 特征像素 = ±2 原生像素），`keep` 项只按 α_prev 减速衰减，是逐位置记忆而非轨迹记忆，与报告 §5.2/§5.4"沿预测轨迹维持响应"的主张不符。
- `trainer.py:458-474` 的 `resid_scr`/`bg_resid_rms` 用**原始帧坐标 GT 框**叠在**锚点坐标残差图**上（prob 做了回投、gt2 未 warp），窗内 31 帧位移未补偿；仅监控不影响判决链，但 M3 的"背景吸收"证据取自它。
- 快评传 `quality=None` 而训练传窗口质量标量，FiLM 第 5 维存在训练/评测口径偏移。

## 五、诚实评价

- **作为工程底座：成立。** 数据 → 对齐 → 窗口 → 损失 → 快评 → 连通域 → 跟踪 → 官方分复刻链路完整、数值良态、97 项单测通过，三个已知致命故障模式被结构性堵住。这部分质量高于对 M3 阶段的通常预期。
- **作为方案声称的那个方法：不成立。** 承担虚警收益的四个构件都不在代码里，α 与 h_T 不进判决链，训练从未跑过。当前 M3 交付的是"一个可训练的液态骨架 + 一套评测管线"，不是背景自适应抑制机制本身。
- **就"能否完成原定目标"：以现在这份代码为基线不能；补齐缺件后能否，取决于第三节 ①② 两条是否被正面处理。** ①是配置级矛盾（τ_B ≫ T），不解决则双状态慢通道是装饰品、消融 (b) 也测不出东西；②是数据级事实，不解决则 F_a 存在由未标注动目标决定的地板，"数量级下降"在任务指标上无从谈起。

## 六、最低成本的证伪顺序（建议，未执行）

1. 先跑一次**状态跨窗续传**（或把 warmup/T 提到 ≥3τ_B）的阶段 B 诊断，看 `F_a@P_d` 与修正坐标系后的 `resid_scr` 是否随慢通道真正收敛而移动——几百步即可判掉"慢通道是否在做功"，比任何 Gate 表都直接。
2. 再决定是否为 gate_head 补 §5.1 的 r_T 支路（EMA 持续性）——它是机理链里唯一承担"孤立亮点 → 压制"的构件，优先级高于并行度优化（阶段 E）。
3. M3 Gate 的 F_a 对照必须在损失组成一致的 single/dual 之间做；两基线至少训到可比的点，否则"降 30%""超基线 +2%"没有分母。
4. 与 ② 相关的 ROI 判别头（§10.7）应尽早排期，否则后续所有 F_a 数字都含无法归因的干扰目标成分。
