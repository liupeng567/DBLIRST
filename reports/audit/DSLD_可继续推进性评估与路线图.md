## 0. 直接回答

**能，而且基础比一般情况更值钱——但前提是先把 M3 核心层返工，而不是接着往下训。**

关键理由是"复用价值"与"返工成本"之间存在明显不对称：

> 这个项目**已经完成的部分恰好是最贵、最难重做的部分；而需要重做的部分恰好是便宜的**（几百行代码，集中在一两个文件里）。

| 层次 | 实况 |
| --- | --- |
| M0 / M1（数据 + 评估基建） | **真交付**，证据链可核验，报告敢写自己的失败项 |
| M2（基线复现） | **只有代码，没有指标** —— Gate 未达成 |
| M3（双状态核心） | **只有代码 + 冒烟**，Gate 未验证；且已暴露可能让核心自我窒息的机制缺陷 |

方案的核心科学主张（P_d ≥ 0.90 约束下 F_a 降 1 个数量级 → 官方总分超最优多帧基线）**至今零证据**：仓库里唯一一次对 `dsld_core` 的端到端评测，`experiments/smoke_dsld_m3c/eval_smoke.json` 显示 `f1: 0.0`、`tp: 0`、官方检测分 `-4757`。

## 1. 可复用性分层

| 层 | 状态 | 判断依据 |
| --- | --- | --- |
| 数据缓存层（87 段 × 10 类文件） | 🟢 **可直接复用** | 逐文件核对齐备；`reg.npz` 含逐帧 rmse/失败标记，`quality.npy` 逐帧清晰度，`labels.npz` RLE + 轨迹索引，`masks.npz` 含 36 个 box_fill 压制标记 |
| 窗口对齐语义（`align_to_anchor` + `bridge_M`） | 🟢 **可直接复用，且是稀缺资产** | 同一矩阵两种 OpenCV flag 语义的换算已独立推导，方向正确；跨参考块连续性这件事自行重写极大概率会做错 |
| 划分与属性标定（manifest v1/v2/v3 + 官方属性表 provenance） | 🟢 **可直接复用** | v1.6 的"val-int 全是傍晚 → 整体对调重平衡"是一次真正的方法论救援，不是形式主义 |
| 评估器（`official_score` 双口径 / `map_iou` / `mask_to_boxes` / `infer_seq`） | 🟢 主体可用，🔴 有两处必须先定 | 缺 IDF1/IDsw；中心点官方分与框级 IoU-F1 会讲相反的故事，主口径必须先统一 |
| 训练壳 `dsld/train/trainer.py` | 🟡 **可用但需补齐** | 单卡能跑；缺 DDP / EMA，续训不等值，早停会丢最优模型 |
| 编码器 + 融合颈（GhostNetV2 截断 + FpnLite） | 🟢 **可复用，且是"容量富矿"** | 结构忠实、FLOPs 大头在此、并行友好。0.111M 对 ≤5M 闸门有 30 倍以上余量 |
| 双状态液态核 `dsld/models/liquid_core.py` | 🔴 **必须返工** | τ 不约束动力学；掩码刀刃条件饿死背景通道；`L_recon` 静默归零。**但全部集中在这一个文件** |
| 损失 `dsld/train/losses.py` | 🟡 两处要修 | `recon_loss` 缺有效像素保护；`decouple_loss` 对 h_T ≡ 0 坍缩无惩罚 |
| M3 Gate 验收协议 | 🔴 **必须重定义** | 现在测的是 θ_τ 参数，不是动力学，对核心假设没有鉴别力 |

### 必须返工项的对应证据（引自评审文档）

- **τ 失效**：`p = σ(−f·dt/τ)` 中 `f` 是自由 1×1 卷积输出（`dsld/models/liquid_core.py:80`），有效时间尺度是 `f/τ`，网络可学 `f ∝ τ` 抵消硬 clip。故"双状态时间尺度分立由结构保证"（`liquid_core.py:5-6`）是过度声明；真正分开两态的只有级联结构与 τ 的**初始化值**。而 M3 Gate 监控的恰是 `theta_tau` 分位数。
- **掩码刀刃条件**：`gate_head` 零初始化使 α ≡ 0.5，掩码用**严格大于** 0.5 判定（`liquid_core.py:112`、`:151-152`）。`experiments/smoke_qe/metrics.jsonl` 实测 `alpha_mean = 0.5003`、`alpha_p99 = 0.502`，但 `alpha_frac_high = 0.94 ~ 0.95` —— 95% 像素以 0.0003 裕度越阈，M ≈ 1 铺满全图，于是 `x_b = x_ctx*(1−M) ≈ 0`、`x_t = x_res*(1−M) ≈ 0`（`liquid_core.py:172-177`），慢通道拿不到输入。
- **监督静默消失**：同一份产物里 `loss_recon: 0.0`；`dsld/train/losses.py:137-150` 在有效像素为空时恰好返回 0 且不告警。
- **损失的盲点**：`decouple_loss` 用 cos²，h_T ≡ 0 时 cos² = 0 → 无惩罚，恰好放过它本要防止的坍缩。

## 2. 为什么这个基础值得继续

自行重建这些资产的成本远高于修核心：

- 21,750 帧的配准 + QC + 跨块桥矩阵；
- 官方评分在口径歧义下的复刻与 R6 回溯条款；
- 三段式划分重平衡（修掉 val-int 全为傍晚的分布失衡）；
- 掩码质检与交汇压制标记（36 个 box_fill 实例）；
- 8 类难点标签与 provenance 标注。

这些是"**几周 + 一定踩坑概率**"的工作，而现在它们是**磁盘上可核验的既成事实**（87 个 `reg.npz`、87 个 `quality.npy`、87 张逐段质检拼图）。

反过来，要改的东西是：τ 的参数化、掩码阈值死区、`recon_loss` 守卫、Gate 度量口径、早停存盘、sweep 标签。**这些加起来是一两天的活**，但决定了后面 55 小时 GPU 是不是白跑。

## 3. 三个还没被验证的硬风险（按危险程度）

### 3.1 机制是否成立，目前零证据，而且现有 Gate 测不出来

`experiments/smoke_qe/metrics.jsonl` 里 `resid_scr` 在 **1.00–1.02** 之间 —— 目标残差与背景残差基本无差别，即"背景吸收背景"这件事**一点都没发生**。同时报告把该现象描述为"方向正确"。

这是最需要警惕的一点：现状不是"训得不够"，而是"**看不出有信号**"。

### 3.2 没有分母

MSHNet 只训了 1 轮 4000 步、无数值（`experiments/mshnet_B/metrics.jsonl` 仅一行），T-MSD3D 未训，`reports/M2_基线复现报告.md` §5 指标表仍是 `<!-- TRAINING_PENDING -->`。没有基线指标，"F_a 降低 X%"这句话目前既无法被证伪也无法被证实。

### 3.3 战略风险：3.1 FPS

目标写着"机载边缘部署候选"，而当前形态是全分辨率 **3.1 FPS**（`experiments/smoke_dsld_m3c/eval_smoke.json` 的 `efficiency.fps_fullres`），成因是 T=32 的逐帧 Python 循环（液态核只占约 2% FLOPs）。

**精度问题可以靠训练解决，吞吐问题是架构问题** —— 它可能反过来否定当前的时序形态。这一点比精度更该早决策。

### 附带一个建设性观察

0.111M 参数（预算的 2%）+ 3.1 FPS，是同一个配置错误的两个症状：**容量放在了 stride-2、逐帧串行的循环核上，而没放在并行友好的编码器上**。把容量上移到编码器、把循环下采样到 stride-4/8 或减少展开步数，**有可能同时改善容量与吞吐**。

## 4. 建议路线

| 阶段 | 内容 | 出口条件 |
| --- | --- | --- |
| **0**（天级，无需 GPU） | 修掩码死区、`recon_loss` 守卫、重定义 Gate（测有效速率 `f·dt/τ` 分布 + 通道分离度 + M 覆盖率 + 有效像素占比）、修早停存盘、统一主口径 | 能在 200 步内看出机制是否在动 |
| **1**（本机，约 7h+） | 把 MSHNet 训到收敛、T-MSD3D 补训 → **拿到分母** | val-int 指标入库，与文献同量级 |
| **2**（本机，短跑） | τ 重参数化 + 掩码修复后的诊断跑（5k 步量级） | **Kill 判据**：`bg_resid` 必须明显下降且 `resid_scr` 必须显著离开 1.0；若 5k 步内两指标都不动，说明双状态分解在 ITTD 上不产生信号 |
| **3**（2×4090） | 先补 DDP，再跑 50k Gate + 单状态消融 | Gate 通过 + 单状态对照给出 F_a 差 |
| **4** | M4 三重门控替换占位 α → M5 跟踪 + 补 IDF1/IDsw | 方案既定 |

### 每阶段"为什么必须在这个顺序"

- 阶段 0 不修，阶段 2/3 的 GPU 时间会被掩码饱和与 `L_recon` 归零直接吞掉；
- 阶段 1 不做，阶段 3 的"F_a 降低 X%"没有分母，无法宣判；
- 阶段 2 的 Kill 判据不设，会带着一个未验证的假设直接消耗 55 小时（本机 crop 档 40k 步的估算时长）。

## 5. 结论，以及什么情况下会改口

**可以作为基础继续推进**，因为已经完成的是"不可逆的贵资产"，待修的是"可逆的便宜代码"。如果直接接着训，浪费的是时间和 GPU；如果放弃重来，浪费的是几周配准/评测基建 —— 两边都不划算。

但有两条清晰的止损线：

1. **机制止损**：阶段 2 的诊断跑里 `resid_scr` 若仍停在 1.0 附近，说明"双状态分解"这一核心假设在 ITTD 上不成立。此时应当诚实降级到更简单的强基线（编码器 + 时序聚合），而不是继续加码 DSLD。
2. **交付止损**：若"实时 / 边缘部署"是硬交付要求，先解决 3.1 FPS 的架构问题再谈精度，否则可能做出一个精度达标但无法交付的东西。
